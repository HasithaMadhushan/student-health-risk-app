# Professional Streamlit UI Design

## Objective

Polish the existing two-step Streamlit interface for the CIS6005 student-health competition demonstrator while preserving the verified CatBoost inference path and every privacy, validation, navigation, and artefact-integrity safeguard.

## Scope and invariants

The redesign changes presentation copy, layout, styling, and UI-focused tests only. It must not change:

- the CatBoost model or model artefact;
- model loading, fail-closed artefact checks, schema validation, or feature order;
- prediction logic, saved class order, or confidence-score calculations;
- numeric missing-value handling or categorical defaults;
- deterministic navigation, state restoration, or reset behaviour;
- the prohibition on identifying fields, input persistence, input logging, and payload logging.

Outputs remain labelled **model confidence scores** and must never be described as calibrated probabilities.

## Selected approach

Use a surgical Streamlit redesign built from the existing native Streamlit controls and session-state functions. Update `app/streamlit_app.py`, `app/presentation.py`, and `app/theme.py` without introducing a frontend framework or restructuring inference code. This approach provides a substantial visual improvement while keeping the smallest regression surface.

## Information architecture

### Global header

- Title: **Student Health Risk Prediction**
- Subtitle: **Enter one record to generate a competition-model prediction.**
- Remove the prominent yellow **Important information** panel and its old session/privacy sentence from every application state.
- Project-owner override (5 August 2026): remove the former medical disclaimer and technical project/model footer metadata from every normal and fail-closed state.

The header is followed by a compact step label and progress bar. The step heading and its supporting copy appear once beneath the progress indicator, avoiding duplicate step titles.

### Step 1

- Label: **Step 1 of 2**
- Heading: **Health-related inputs**
- Supporting text: **Complete the available fields. Optional numeric values may be left blank.**
- Existing features, in their existing schema mappings:
  - `sleep_duration`
  - `heart_rate`
  - `bmi`
  - `sleep_quality`
  - `stress_level`
- Primary action: **Continue**

### Step 2

- Label: **Step 2 of 2**
- Heading: **Daily routine inputs**
- Supporting text: **Complete the remaining fields, review the record and generate a result.**
- Existing features, in their existing schema mappings:
  - `calorie_expenditure`
  - `step_count`
  - `exercise_duration`
  - `water_intake`
  - `physical_activity_level`
  - `diet_type`
  - `smoking_alcohol`
- Expander: **Review entered values**
- Secondary action: **Back**
- Primary action: **Generate prediction**

### Result state

The result state replaces the form body with a professional bordered card:

- Heading: **Prediction result**
- Label: **Predicted competition category**
- Prominent, text-labelled predicted class
- Neutral sentence: **This category was generated by the trained competition model.**
- Expander: **View model confidence scores**
- Three confidence scores displayed in the saved model class order using labelled horizontal progress rows
- Caption: **These are model confidence scores, not calibrated probabilities.**
- Primary action: **Start a new prediction**

The **Review entered values** expander remains below the result card and uses only friendly labels and formatted values.

### Footer

Do not render a footer, medical disclaimer, course/project label, or model-family label. This owner decision supersedes the earlier footer design while leaving model behaviour and privacy safeguards unchanged.

## Visual system

Use a centred content column with a maximum width near 900 px. The design follows a calm, professional healthcare-data palette with restrained cyan/teal accents and neutral surfaces:

- dark readable foreground on a soft near-white background;
- white cards with subtle borders;
- one accessible teal primary action colour;
- muted slate secondary text;
- red reserved for error states;
- visible, high-contrast focus rings.

Use a consistent 4/8 px spacing rhythm, 12-16 px radii, input heights of at least 48 px, and minimal shadows. Remove the radial background decoration and avoid gradients. Use responsive CSS so the native two-column Streamlit layout collapses naturally on smaller screens without horizontal scrolling. Preserve reduced-motion rules.

## Form behaviour

Numeric fields remain blank by default, retain their current units, precision, bounds, steps, and example placeholders. Categorical fields retain **Select an answer** as the empty prompt and **Not sure** as the missing-value option; no real category is preselected.

Input values remain only in Streamlit session state. Back and Continue call the existing state-storage functions, so values are restored when users navigate. Prediction executes only in response to the keyed **Generate prediction** button. A successful result is stored before `st.rerun()`, preventing reruns from invoking prediction again.

## Error handling

Schema or model loading failures remain fail-closed and use a concise `st.error` message without a traceback. Input or inference failures use a short recovery-oriented error asking the user to review the record and try again. Existing validation exceptions remain unchanged; no exception details, internal paths, hashes, Python representations, or payload data are displayed.

## Accessibility and responsive behaviour

- Keep native Streamlit labels and controls for keyboard and screen-reader support.
- Maintain visible focus states and minimum 44 px interactive targets.
- Do not communicate result or progress state through colour alone; retain text labels and numeric score text.
- Keep body text at or above 16 px with comfortable line height.
- At desktop/tablet widths, use two columns; at mobile widths, allow Streamlit to collapse to one column and make actions full-width.
- Retain `prefers-reduced-motion` support.

## Testing strategy

Follow test-driven development for each presentation change:

1. Update UI text tests so they fail against the current interface.
2. Add explicit assertions that the yellow warning panel and old technical/session copy are absent while the exact compact mandatory medical disclaimer is present in Step 1, Step 2, the result state, and fail-closed startup output.
3. Add or update assertions for the requested headings, actions, review expander, result card, confidence-score expander, and footer.
4. Preserve and run all inference, schema/class-order, deterministic prediction, validation, privacy/non-persistence, artefact-failure, navigation/reset, and theme-accessibility tests.
5. Run the complete `pytest` suite and report collected, passed, failed, skipped, and warning counts exactly.
6. Run the app locally and verify Step 1, Step 2, result, Back, Continue, Generate prediction, review, reset, valid input, optional missing input, invalid input, responsive layout, privacy, and unchanged model/schema artefacts.

## Acceptance criteria

The work is complete only when the requested copy and visual hierarchy are visible in all three states, the removed yellow panel is absent everywhere, the exact compact mandatory medical disclaimer remains visible in every normal and fail-closed state, no identifying or persistent input handling is introduced, the model/schema artefact hashes remain unchanged, and the full test suite completes with no unresolved failures.
